Project overview

A workshop for agentic software work.

Atelier is a self-hosted web control plane that turns repositories into isolated Docker workspaces where people, coding agents, terminals, browsers, and IDEs work side by side.

01 / Identity

What the project is

Atelier owns the full workspace lifecycle: it prepares source, resolves an image, starts a container, attaches tools, proxies apps, runs coding-agent sessions, and protects work during deletion.

01

Workspaces are the unit of work

Every task gets an isolated source tree and Docker runtime. Workspaces may start empty, from a saved project, or as a fork of another workspace.

02

The server owns the interface

HTML and Turbo Stream responses are rendered on the server. Stimulus is reserved for browser-only behavior such as tabs, dialogs, and WebSocket terminals.

03

Capabilities arrive as modules

Packages contribute tabs, commands, routes, sockets, provisioning hooks, apps, static files, and settings through a generated workspace-module registry.

02 / Architecture

03 / Core flow

From repository to live agent

The main path is asynchronous and observable: creation returns immediately, while provisioning status and terminal output stream into the workspace view.

Entry points

The web UI and POST /api/workspaces both create workspaces. An optional initial prompt, model, and thinking level can be supplied up front.
01

Choose or register a project

A saved Git project provides repository identity, reusable source templates, GitHub credentials, shared persistent data, and repository-specific workspace configuration.

02

Create the host workspace

Atelier prepares an empty source tree, a project-backed worktree, or a fork of an existing workspace and records its runtime metadata.

03

Plan and resolve the image

The workspace manifest and Dockerfile determine the image. Deterministic image tags allow builds and nested-Docker preload carriers to be reused.

04

Start and provision the container

Docker mounts the source and persistent data, publishes supported ports on host loopback, then runs setup hooks while detailed progress streams to the UI.

05

Attach the working surfaces

Workspace modules contribute agent, terminal, browser, VS Code, and desktop tabs. The layout system places them into visible and preview groups.

06

Run, inspect, and iterate

The Pi agent streams work into server-rendered views while users open live tmux terminals, preview app ports, browse, or enter the embedded IDE.

07

Protect work at teardown

Deletion checks for uncommitted and unpushed changes first. Unsafe deletion is surfaced for explicit confirmation instead of silently dropping work.

05 / Networking

Loopback is the portable boundary

Atelier deliberately avoids container IPs and Docker DNS for workspace app ingress. Supported app ports are published to host loopback and the control plane connects there.

Workspace app ingress

Browser, VS Code, desktop, and arbitrary preview ports flow through the Atelier ingress proxy to an allocated loopback port.

browser→Atelier ingress→127.0.0.1:port→workspace
publish host: 127.0.0.1
connect host: 127.0.0.1

Deployment implication

A host app works on macOS through Docker Desktop port forwarding. A containerized Atelier deployment is a Linux shape and must use host networking.

Atelier container→host namespace→published port
docker run --network host … atelier:latest
06 / Development

A Bun-first toolchain

Root scripts generate module registries before type checks and tests. The same repository builds the web runtime image and its default workspace image.

# Start the development web app
bun run web

# Generate module imports + type-check
bun run check

# Generate module imports + run tests
bun run test

# Frozen install, checks, and tests
bun run ci

# Build or run the Dockerized product
bun run image:build
bun run image:build
Type systemStrict TypeScript 6, ESM, no emit, workspace aliases.
Client buildBun asset script bundles Turbo, Stimulus, module clients, and static assets.
UI conventionPrefer server-rendered HTML and Turbo Streams; keep Stimulus controllers small.
Container buildapps/web/Dockerfile performs a frozen install, asset build, runtime assembly, and exposes port 3000.
