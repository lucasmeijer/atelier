When a good rule mistakes evidence for slop

These rules are directionally useful. The problem is their unit of observation: syntax alone cannot always tell an unprincipled escape hatch from a parser, a runtime union, or a framework seam. This note uses current Atelier code to draw that boundary.

Rule 01

no-runtime-typeof

The slop it prevents. Code receives a vaguely typed value, probes it with scattered typeof checks, and quietly grows a second, incomplete type system at runtime. The rule pushes validation toward an explicit I/O boundary and domain types.

The JSON boundary is the parser

packages/core/src/json-request.ts:13
function isJsonValue(value: unknown): value is JsonValue {
  return value === null
    || typeof value === "boolean"
    || (typeof value === "number" && Number.isFinite(value))
    || typeof value === "string"
    || (Array.isArray(value) ? value.every(isJsonValue) : isJsonObject(value));
}
Why exempt it

This function is exactly the boundary the diagnostic asks for. JSON has runtime tags, and a recursive type guard must inspect them to establish the contract. Moving these checks elsewhere would only rename the parser or replace evidence with an assertion.

A manifest parser must describe failures precisely

packages/workspace/src/index.ts:211
const dockerRecord = optionalRecord(record, "docker", path);
if (dockerRecord?.privileged !== undefined
  && typeof dockerRecord.privileged !== "boolean")
  throw invalidArguments(`invalid ${path}: docker.privileged must be a boolean`);

if (initScripts !== undefined && (!Array.isArray(initScripts)
  || !initScripts.every((script) => typeof script === "string")))
  throw invalidArguments(`invalid ${path}: initScripts must be an array of strings`);
Why exempt it

This is the repository manifest’s I/O boundary. Inline checks allow field-specific error messages and create a typed manifest only after every relevant invariant holds. A schema library could express the same work, but it would not make the runtime checks less necessary.

Recommended boundary: flag ad-hoc typeof narrowing in ordinary domain functions, but recognize declared type guards, parser/decoder functions, and unions supplied by platform APIs. An explicit boundary annotation would cover cases syntax cannot infer.

Rule 02

no-unknown-parameters

The slop it prevents. A function accepts unknown because its author has not decided what it owns, then spreads narrowing and assertions through every caller. The rule asks APIs to accept domain types and parse external values before calling them.

Promise rejection reasons are unknown by contract

packages/update/src/server/index.ts:101
private fail(error: unknown): void {
  this.setState("failed", {
    error: error instanceof Error ? error.message : String(error),
  });
}
Why exempt it

JavaScript permits throwing any value. A rejection handler that claims Error would lie; this function responsibly normalizes the throwable immediately. Renaming the parameter to an exempt word would merely game the rule.

Recommended boundary: keep rejecting unknown in ordinary application APIs, but exempt type guards/decoders, throwable callbacks, and explicitly declared transport or extension seams. Prefer an annotation or typed marker interface over parameter-name heuristics.

Rule 03

require-safety-comment-for-type-assertion

The slop it prevents. An assertion erases compiler evidence and replaces it with author confidence. Requiring a nearby SAFETY: note makes the missing invariant visible in review and discourages casual casts.

Bun implements an overload missing from DOM types

packages/proxy-ingress/src/ingress/index.ts:362
function openWorkspaceAppProxySocket(ws: ServerWebSocket<WorkspaceAppProxySocketData>): void {
  const WebSocketWithOptions = WebSocket as typeof WebSocket &
    (new (url: string | URL, options: Bun.WebSocketOptions) => WebSocket);
  const upstream = new WebSocketWithOptions(ws.data.target, {
    headers: { Host: ws.data.host }, protocols: ws.data.protocols,
  });
}
Why exempt it

This preserves the standard constructor and adds Bun’s documented options overload, which the ambient DOM declaration lacks. The assertion corrects an environment typing gap; it does not narrow an untrusted runtime value.

Recommended boundary: require justification primarily for assertions originating in unknown/any or external boundary expressions. Exempt tests, known framework adapters, and ambient-type augmentation—or make those exemptions explicit in configuration. Type-aware assignability is needed to distinguish a real downcast from harmless interop.
