When a good rule mistakes evidence for slop

These rules are directionally useful. The problem is their unit of observation: syntax alone cannot always tell an unprincipled escape hatch from a parser, a runtime union, or a framework seam. This note uses current Atelier code to draw that boundary.

Rule 01

no-runtime-typeof

The slop it prevents. Code receives a vaguely typed value, probes it with scattered typeof checks, and quietly grows a second, incomplete type system at runtime. The rule pushes validation toward an explicit I/O boundary and domain types.

The JSON boundary is the parser

packages/core/src/json-request.ts:13
function isJsonValue(value: unknown): value is JsonValue {
  return value === null
    || typeof value === "boolean"
    || (typeof value === "number" && Number.isFinite(value))
    || typeof value === "string"
    || (Array.isArray(value) ? value.every(isJsonValue) : isJsonObject(value));
}
Why exempt it

This function is exactly the boundary the diagnostic asks for. JSON has runtime tags, and a recursive type guard must inspect them to establish the contract. Moving these checks elsewhere would only rename the parser or replace evidence with an assertion.

Persisted settings need field validation

packages/projects/src/git-identity.ts:26
const candidate = parsed.gitIdentity;
if (!(candidate instanceof Object) || !("name" in candidate) || !("email" in candidate)) return {};
const name = typeof candidate.name === "string" ? candidate.name.trim() : "";
const email = typeof candidate.email === "string" ? candidate.email.trim() : "";
return name && email ? { gitIdentity: { name, email } } : {};
Why exempt it

The file can be old, edited by a human, or partially corrupt. Rejecting non-string fields before constructing GitIdentitySettings is the evidence that makes the returned type trustworthy.

A manifest parser must describe failures precisely

packages/workspace/src/index.ts:211
const dockerRecord = optionalRecord(record, "docker", path);
if (dockerRecord?.privileged !== undefined
  && typeof dockerRecord.privileged !== "boolean")
  throw invalidArguments(`invalid ${path}: docker.privileged must be a boolean`);

if (initScripts !== undefined && (!Array.isArray(initScripts)
  || !initScripts.every((script) => typeof script === "string")))
  throw invalidArguments(`invalid ${path}: initScripts must be an array of strings`);
Why exempt it

This is the repository manifest’s I/O boundary. Inline checks allow field-specific error messages and create a typed manifest only after every relevant invariant holds. A schema library could express the same work, but it would not make the runtime checks less necessary.

The platform API defines a real runtime union

packages/observable-terminal/src/client/index.ts:169
ws.onmessage = (event) => {
  if (typeof event.data === "string") {
    options.onOutput?.(event.data);
    term.write(event.data);
  } else event.data.arrayBuffer().then((buffer: ArrayBuffer) => {
    const data = new Uint8Array(buffer);
    options.onOutput?.(data);
    term.write(data);
  });
};
Why exempt it

MessageEvent.data is intentionally polymorphic. The branch selects the platform-supported text and binary paths; there is no single domain value to parse first, and coercing either branch would alter terminal bytes.

Recommended boundary: flag ad-hoc typeof narrowing in ordinary domain functions, but recognize declared type guards, parser/decoder functions, and unions supplied by platform APIs. An explicit boundary annotation would cover cases syntax cannot infer.

Rule 02

no-unknown-parameters

The slop it prevents. A function accepts unknown because its author has not decided what it owns, then spreads narrowing and assertions through every caller. The rule asks APIs to accept domain types and parse external values before calling them.

A decoder cannot require decoded input

packages/core/src/json-request.ts:13
function isJsonValue(value: unknown): value is JsonValue { /* validation */ }

export function isJsonObject(value: unknown): value is JsonObject {
  return typeof value === "object" && value !== null
    && !Array.isArray(value) && Object.values(value).every(isJsonValue);
}
Why exempt it

The function’s purpose is to decide whether an external value is a JsonObject. Requiring a domain type at its entry would assume the fact it exists to prove and make the guard unusable at actual boundaries.

Promise rejection reasons are unknown by contract

packages/update/src/server/index.ts:101
private fail(error: unknown): void {
  this.setState("failed", {
    error: error instanceof Error ? error.message : String(error),
  });
}
Why exempt it

JavaScript permits throwing any value. A rejection handler that claims Error would lie; this function responsibly normalizes the throwable immediately. Renaming the parameter to an exempt word would merely game the rule.

Transport extension points defer ownership

packages/shared/src/index.ts:186
export interface WorkspaceServerSocketHandler {
  validate?(request: Request, url: URL): WorkspaceServerSocketData | undefined;
  open?(socket: unknown): void;
  message?(socket: unknown, message: unknown): void;
  close?(socket: unknown): void;
}
Why exempt it

The shared registry intentionally does not depend on Bun’s socket type or a module-specific message format. Each registered owner narrows the opaque transport values at its adapter. Making the shared package name every implementation type would invert the dependency.

OpenAPI schemas are opaque extension data

apps/web/src/server/openapi.ts:7
const jsonResponse = (description: string, schema: unknown, status = "200") => ({
  [status]: { description, content: { "application/json": { schema } } },
  "400": errorResponse,
  "404": errorResponse,
});

const jsonBody = (schema: unknown) => ({
  required: true, content: { "application/json": { schema } },
});
Why exempt it

Workspace modules contribute schemas from an external schema system. This layer stores and emits them; it does not interpret them. A home-grown “schema” type would either be inaccurate or recreate the upstream library’s open extension vocabulary.

Agent SDK payloads are decoded by their consumer

packages/agent/src/server/runtime.ts:399
protected liveToolCallComplete(callId: string, name: string, args: unknown): void {
  // Store the SDK event first; the selected tool renderer owns its shape.
  live.items.push({ type: "tool", tool: { callId, name, args, status: "running" } });
  if (name === "bash") {
    const timeout = (args as { timeout?: number } | undefined)?.timeout;
    // …bash-specific interpretation…
  }
}
Why exempt it

The SDK deliberately gives tool arguments an open shape because every tool owns a different schema. The runtime must retain opaque payloads for generic rendering, while specialized consumers decode only the fields they own.

Recommended boundary: keep rejecting unknown in ordinary application APIs, but exempt type guards/decoders, throwable callbacks, and explicitly declared transport or extension seams. Prefer an annotation or typed marker interface over parameter-name heuristics.

Rule 03

require-safety-comment-for-type-assertion

The slop it prevents. An assertion erases compiler evidence and replaces it with author confidence. Requiring a nearby SAFETY: note makes the missing invariant visible in review and discourages casual casts.

A schema engine already validated the command

packages/browser/src/server/web.ts:34
commands: [{
  inputSchema: Type.Object({ url: Type.Optional(Type.String()) }),
  execute({ workspaceId, input }) {
    const browser = createWorkspaceBrowserTab(workspaceId);
    const url = (input as { url?: string }).url;
    if (url) setWorkspaceBrowserTarget(workspaceId, browser.key, url);
  },
}]
Why exempt it

The command framework validates input against the adjacent TypeBox schema before execution. The cast bridges a generic framework type that does not carry the schema’s static type. Repeating a comment at every command adds ceremony without new evidence.

The shared socket seam is intentionally erased

packages/agent/src/server/web.ts:136
context.registerSocketHandler({
  validate: (_request, url) => validateAgentTermSocket(url),
  open: (socket) => openAgentTermSocket(socket as Parameters<typeof openAgentTermSocket>[0]),
  message: (socket, message) => handleAgentTermSocketMessage(
    socket as Parameters<typeof handleAgentTermSocketMessage>[0],
    message as string | Buffer,
  ),
});
Why exempt it

The registry erases implementation-specific socket types to avoid coupling shared code to Bun and individual modules. Registration is the adapter where the concrete handler and its validated socket data are reunited. The assertion documents that architectural seam in types.

DOM event targets lose the markup contract

packages/files/src/client/index.ts:57
folderDragEnter(event: DragEvent): void {
  if (!this.hasFiles(event)) return;
  event.preventDefault();
  event.stopPropagation();
  (event.currentTarget as HTMLElement).classList.add("is-drop-target");
}

toggleHidden(event: Event): void {
  this.navigateFrame(this.listingUrl((event.currentTarget as HTMLInputElement).checked));
}
Why exempt it

Stimulus actions are attached by server-rendered markup to known element kinds, but the DOM event API exposes only EventTarget. The missing evidence lives in HTML, beyond a syntax-only TypeScript rule. Per-handler comments would duplicate that markup contract dozens of times.

A test has just asserted the runtime type

packages/proxy-egress/test/secrets/placeholder-hooks.test.ts:18
const result = await hooks.httpHooks.onRequest!(new Request("https://api.github.com/user", {
  headers: { authorization: "Bearer ATELIER_SECRET_fake" },
}));
expect(result).toBeInstanceOf(Request);
expect((result as Request).headers.get("authorization")).toBe("Bearer real-secret");
Why exempt it

The line immediately above is the runtime proof, but Bun’s matcher does not narrow the following expression. A mandatory prose comment would restate the assertion. Test code often needs casts to inspect deliberately partial fixtures and union results after expectations.

Bun implements an overload missing from DOM types

packages/proxy-ingress/src/ingress/index.ts:362
function openWorkspaceAppProxySocket(ws: ServerWebSocket<WorkspaceAppProxySocketData>): void {
  const WebSocketWithOptions = WebSocket as typeof WebSocket &
    (new (url: string | URL, options: Bun.WebSocketOptions) => WebSocket);
  const upstream = new WebSocketWithOptions(ws.data.target, {
    headers: { Host: ws.data.host }, protocols: ws.data.protocols,
  });
}
Why exempt it

This preserves the standard constructor and adds Bun’s documented options overload, which the ambient DOM declaration lacks. The assertion corrects an environment typing gap; it does not narrow an untrusted runtime value.

Recommended boundary: require justification primarily for assertions originating in unknown/any or external boundary expressions. Exempt tests, known framework adapters, and ambient-type augmentation—or make those exemptions explicit in configuration. Type-aware assignability is needed to distinguish a real downcast from harmless interop.
