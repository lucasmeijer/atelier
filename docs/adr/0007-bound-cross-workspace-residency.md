# Bound cross-workspace residency and preload Agent-ready workspaces

Atelier keeps at most three Workspace presentations resident in each browser on both desktop and mobile. The visible Workspace is always resident; remaining capacity goes first to the Workspaces whose uninterrupted Agent-ready episodes have waited longest, then to recently activated residents. Agent ready is the only speculative-preload trigger: a preload mounts the complete server-rendered Workspace without firing `onBecomeVisible`, activating visibility-scoped resources, or acknowledging readiness. Each browser computes residency independently, while Agent ready and its genuine acknowledgement remain shared persistent state.

Eviction removes only that browser's presentation, never its server-side agents or Work-view resources. It must first persist user-authored work and promised Personal navigation state, and it cannot proceed when that persistence fails; resource ownership and explicit close or Workspace deletion govern server lifetimes. Re-entry restores structural state before interaction, while focus, transient dialogs, fullscreen, editor undo history, and unpersistable iframe history or JavaScript state may be reconstructed or lost.

This fixed, readiness-driven policy rejects unlimited residency, unreliable browser memory-pressure heuristics, hover prediction, and user-facing pin or eviction controls. It spends bounded browser resources on the Workspaces the product knows the user is waiting for, while keeping visibility, acknowledgement, and resource lifetime as separate concepts.
