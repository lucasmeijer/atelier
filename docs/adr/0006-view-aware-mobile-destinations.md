# Use view-aware mobile destinations

Atelier phone layouts show one surface at a time and use a stable bottom destination bar for Workspace, every open Agent conversation, and open File, Browser, and Terminal Work views. Direct destinations squeeze to a minimum width before scrolling between fixed Workspace and More controls. More opens a bottom sheet with separate sections for Files, Changes, and VS Code Work views and for launchers that create or reveal Work views. Selecting a secondary view leaves More highlighted and the bottom bar unchanged, and singleton Files and Changes launchers remain available after their live views close. New Agent remains in the Agent surface. Work remains internal domain language rather than a mobile navigation label. Work-view Attention dots appear on direct Work-view destinations and entries within More, with More signaling hidden Work-view Attention; Agent-conversation destinations never show them. Every closable destination requires a view-specific confirmation before explicit close removes its persistent state. Switching destinations hides rather than unmounts every open Agent conversation and Work view. This model preserves direct access and live state without forcing every view into permanent phone navigation.
